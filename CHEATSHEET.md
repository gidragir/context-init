# 📖 Шпаргалка по командам и сценариям `context-init`

CLI-утилита для генерации, поддержания и упаковки компактной трехуровневой базы знаний (**OpenViking L0–L2**) для ИИ-ассистентов (Antigravity, Hermes, Claude Code, Cursor, Aider).

---

## 🗺 Концепция уровней OpenViking

| Уровень | Файл / Директория | Назначение | Объем токенов |
| :--- | :--- | :--- | :--- |
| **L0 (Mental Map)** | `.agents/knowledge/L0_index.md` | Глобальная карта проекта, архитектурные слои, таблица подсистем | ~500–700 |
| **L0 (Metadata)** | `.agents/knowledge/L0_index.json` | Машиночитаемая схема проекта, точки входа, BPE-токенометрия | ~1 000–1 500 |
| **L1 (Subsystems)** | `.agents/knowledge/subsystems/<id>.md` | Карточки модулей: назначение, файлы, публичные AST-контракты | ~200–400 на модуль |
| **L2 (Commands)** | `.agents/knowledge/cli/commands.md` | Справочник проверенных команд жизненного цикла (build, test, lint) | ~150–250 |
| **ADR (Decisions)**| `.agents/knowledge/adr/0001_*.md` | Архитектурные решения и принятые проектные инварианты | ~300–600 |

---

## 🛠 Справочник команд и опций

### 1. `init` — Первичная инициализация базы знаний

Создает полную структуру `.agents/knowledge/` и корневой `AGENTS.md`.

```bash
context-init init [OPTIONS] [PATH]
```

#### Ключевые флаги:
- `--deep` — Глубокий AST-парсинг исходников: извлечение сигнатур функций, структур, типов, трейтов и интерфейсов (Rust через `syn`, TS/Python/Go через многострочный автомат).
- `--compact` — Однострочный машиночитаемый вывод `OK: initialized N subsystems...` без ASCII-баннеров (для агентов и скриптов).
- `-f, --force` — Принудительная перезапись существующей базы знаний с нуля.
- `--dry-run` — Предварительный просмотр структуры без внесения изменений на диск.
- `--model <ALIAS>` — Алиас модели из `[models]` конфига для всех ролей (Ollama, command, agent, ...).
- `--role <ROLE>=<ALIAS[,ALIAS]>` — Цепочка моделей для роли `init|update|task|search` (повторяемый).
- `--config <FILE>` — Дополнительный конфиг поверх проектного и глобального.
- `--with-rtk` — Принудительно оборачивать команды в префикс `rtk` (по умолчанию: автодетекция в `$PATH`).
- `--no-rtk` — Отключить оборачивание команд в `rtk`.
- `--no-agents-md` — Не создавать и не обновлять навигационный раздел в корневом `AGENTS.md` (по умолчанию обновляется).

---

### 2. `check` — Аудит архитектурного дрейфа

Сверяет текущую файловую структуру репозитория с базой знаний. Время выполнения: <10 мс.

```bash
context-init check [OPTIONS] [PATH]
```

#### Ключевые флаги:
- `--compact` — Машиночитаемый однострочный вывод:
  - При отсутствии дрейфа: `OK: N subsystems up-to-date`
  - При наличии дрейфа: `DRIFT: up_to_date=N, missing=[...], untracked=[...]`
- `--exit-code` — Завершать процесс с кодом возврата `1` при обнаружении дрейфа (для pre-commit и CI/CD). При отсутствии дрейфа возвращает `0`.

---

### 3. `update` — Инкрементальная синхронизация

Добавляет новые подсистемы в базу знаний и обновляет метаданные существующих, **не затирая ручные заметки** разработчика в L1-карточках.

```bash
context-init update [OPTIONS] [PATH]
```

#### Ключевые флаги:
- `--compact` — Однострочный машиночитаемый вывод: `OK: updated N subsystems...`.
- `--deep` — Повторное AST-сканирование контрактов для вновь обнаруженных модулей.
- `--model <ALIAS>` / `--role update=<ALIAS>` — Модель из конфига для описаний новых подсистем.
- `--with-rtk` / `--no-rtk` — Управление префиксом команд `rtk`.

---

### 4. `pack` — Упаковка контекста подсистемы

Собирает исходный код файлов целевой подсистемы в компактный формат для контекстного окна LLM. По умолчанию использует быстрый встроенный AST-компрессор на чистом Rust (~30 мс, экономия токенов до 89%).

```bash
context-init pack [OPTIONS] <SUBSYSTEM_ID> [PATH]
```

#### Аргументы:
- `<SUBSYSTEM_ID>` — Идентификатор подсистемы из `L0_index.json` (например: `core`, `detector`, `generator`) либо `all` для упаковки всех подсистем проекта.

#### Ключевые флаги:
- `--compress` — AST-сжатие контекста: замена тел функций на `⋮----` (включено по умолчанию).
- `--no-compress` — Отключить сжатие: выгрузка полного verbatim-исходного кода.
- `-o, --output <PATH>` — Файл для сохранения пакета. Если передан `-o -` или опция опущена при перенаправлении, вывод идет в `stdout`.
- `--style <xml|markdown>` — Формат разметки пакета (по умолчанию: `xml`).
- `--repomix` — Делегировать упаковку во внешнюю утилиту Repomix (Node.js) вместо встроенного компрессора.

## 🚀 Практические сценарии использования

### Сценарий 1: Первичная настройка репозитория (Onboarding)

```bash
# Рекомендуемый базовый запуск с точным AST-парсингом:
context-init init . --deep

# Запуск с обогащением описаний модулей моделью из конфига ([models.local]):
context-init init . --deep --model local

# Безопасная проверка структуры перед записью:
context-init init . --deep --dry-run
```

---

### Сценарий 2: Интеграция в Git Pre-commit хуки (Lefthook / Husky)

Предотвращает коммит кода с недокументированными модулями или удаленными папками.

#### Пример конфигурации `lefthook.yml`:
```yaml
pre-commit:
  commands:
    context-drift-check:
      run: context-init check --compact --exit-code .
```

#### Ручной запуск проверки:
```bash
context-init check --compact --exit-code .
# Вывод при успехе: OK: 5 subsystems up-to-date (код 0)
# Вывод при дрейфе: DRIFT: up_to_date=5, missing=[], untracked=[src_analytics] (код 1)
```

---

### Сценарий 3: Когнитивный цикл автономного ИИ-агента

Устраняет контекстный шум и экономит до 95% лимита контекстного окна:

1. **Фаза ориентации:**
   Агент считывает компактную ментальную карту проекта (~600 токенов):
   ```bash
   cat .agents/knowledge/L0_index.md
   ```

2. **Фаза локализации:**
   Агент читает контракт нужного модуля (~300 токенов):
   ```bash
   cat .agents/knowledge/subsystems/src_detector.md
   ```

3. **Фаза загрузки интерфейсов:**
   Агент получает все сигнатуры и типы подсистемы со скрытыми телами функций (~1 450 токенов вместо 13 000):
   ```bash
   context-init pack detector -o -
   ```

4. **Фаза валидации:**
   Агент запускает проверенную команду из `cli/commands.md`:
   ```bash
   cargo test
   ```

---

### Сценарий 4: Добавление нового модуля в проект

Если вы добавили новую папку или крейт (например, `src/billing`):

```bash
# 1. Проверяем наличие дрейфа:
context-init check .

# 2. Инкрементально добавляем новую карточку в базу знаний:
context-init update . --deep

# 3. Проверяем, что дрейф устранен:
context-init check --compact .
```

---

### Сценарий 5: Полная регенерация базы знаний

Если архитектура проекта кардинально изменилась и требуется пересоздать все L1-карточки со свежими AST-сигнатурами:

```bash
context-init init . --force --deep
```

---

### Сценарий 6: Подготовка контекста для веб-интерфейсов LLM (ChatGPT / Claude)

Сборка всей кодовой базы или отдельного сервиса в единый файл для отправки в диалоговое окно:

```bash
# Сжатый XML-пакет целевой подсистемы:
context-init pack detector -o /tmp/detector.xml

# Полный несжатый код всего проекта в формате Markdown:
context-init pack all --no-compress --style markdown -o /tmp/project_full.md

# Упаковка через Node.js Repomix (если требуются специфичные правила .repomixignore):
context-init pack all --repomix -o /tmp/project_repomix.xml
```

---

### Сценарий 7: Автономное окружение без внешних зависимостей (Offline / Air-gapped)

Утилита полностью автономна и не требует Node.js, Python или доступа в интернет:

```bash
# Инициализация без обращения к LLM (детерминированный режим по умолчанию):
context-init init . --deep

# Сжатие и упаковка через встроенный Rust-пакер без Repomix:
context-init pack all -o /tmp/context.xml
```

## ⚡️ Матрица быстрого подбора команд

| Задача | Рекомендуемая команда |
| :--- | :--- |
| Создать базу знаний впервые | `context-init init . --deep` |
| Создать базу знаний с нейросетью | `context-init init . --deep --model local` |
| Проверить актуальность перед коммитом | `context-init check --compact --exit-code .` |
| Синхронизировать новые модули | `context-init update . --deep` |
| Полностью пересоздать документацию | `context-init init . --force --deep` |
| Получить сжатый контекст модуля | `context-init pack <id> -o -` |
| Получить полный код модуля в файл | `context-init pack <id> --no-compress -o pack.xml` |
| Упаковать проект в Markdown | `context-init pack all --style markdown -o pack.md` |
