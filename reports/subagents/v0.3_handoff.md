## 2. Локализованный дефект Шага 4 (Готовое ТЗ для исправления)

### Суть проблемы
Тест `pagination::tests::multibyte_utf8_truncation_does_not_panic_and_preserves_boundaries` уходит в бесконечный цикл (100% CPU) в `crates/ci-mcp/src/pagination.rs:308-316`.

```rust
// crates/ci-mcp/src/pagination.rs:308-316
let backoff = (split_len / 10).max(1).min(split_len.saturating_sub(1));
let new_len = split_len.saturating_sub(backoff);
split_len = find_valid_char_boundary(remaining, new_len);
if split_len == 0 {
    split_len = find_next_char_boundary(remaining, 1);
    if split_len >= remaining.len() {
        break;
    }
}
```

### Механика сбоя
Когда `remaining` начинается с многобайтового символа (кириллица, 2 байта):
1. При `split_len == 2`, `new_len` вычисляется как `1`.
2. Индекс `1` не является границей UTF-8 символа. `find_valid_char_boundary(remaining, 1)` возвращает `0`.
3. Условие `if split_len == 0` срабатывает, и `find_next_char_boundary(remaining, 1)` перескакивает вперед на следующую границу — снова `2`!
4. `split_len` циклически колеблется `2 -> 0 -> 2 -> ...`, вызывая бесконечный цикл `loop`.

### Решение
Заменить откат на строгий поиск **предыдущей** границы символа:
- Использовать `find_prev_char_boundary(remaining, split_len)` (или `remaining[..split_len].char_indices().last()`).
- Если `split_len` достигает длины первого символа (или 0), немедленно вызывать `break;`.

## 4. Сквозные инварианты хоста для сохранения контекста
1. **Только `rtk`**: Любые shell-команды вызываются строго с префиксом `rtk` (`rtk cargo ...`, `rtk git ...`, `rtk rg`, `rtk fd`).
2. **Только `fd` и `rg`**: Использование GNU `find` и GNU `grep` категорически запрещено.
3. **Mise shims**: Перед вызовом cargo всегда экспортировать `export PATH="${__MISE_ZSH_ACTIVATE_PATH:-$HOME/.local/share/mise/shims}:$PATH"`.
4. **Инвариант нейтральности**: Строго ноль упоминаний «1С» / «1C» в кодовой базе, комментариях и тестах.
5. **Центральное хранилище**: База знаний L0–L2 в runtime располагается в `~/.local/share/context-init/projects/<project-id>/`.
6. **Субагентный контекстный мост (D31)**: Воркеры субагентов не имеют MCP-инструментов. Супервайзер обязан инжектировать AST-срез (`context_pack`) в секцию `**Context**` промпта, а в правилах требовать вызов CLI `rtk context-init pack <subsystem_id> --compress` вместо негативного запрета чтения файлов.
