## 2. Глубокий критический анализ: доказательства завершения

### 2.1. `find_split_point` (`pagination.rs:327-372`)
Инвариант: `0 ≤ low`, `high ≤ text.len()`, цикл идет, пока `low ≤ high`. Пусть `mid = (low+high)/2`, тогда `low ≤ mid ≤ high`, а `mid_boundary ≤ mid`.
- Ветка `tokens ≤ target`: `low' = mid + 1 > low`, расстояние `high − low` строго уменьшается.
- Ветка `tokens > target`: если `mid_boundary == 0`, выполняется `break` (так исключено опустошение `usize`). Иначе `high' = mid_boundary − 1 ≤ mid − 1 < high`, т.е. строго уменьшается.

Мера `high − low + 1` строго убывает на каждой итерации, поэтому цикл завершается за O(n) шагов. На монотонном (по префиксу) счетчике токенов это O(log n) шагов. `best_split` всегда равен `find_valid_char_boundary(..)`, т.е. это граница символа. Пост-обработка по `\n` (`:357-369`) выдает `candidate ∈ (search_start, best_split]`, тоже на границе: `\n` однобайтовый, а `search_start` снэпнут.

### 2.2. Цикл обрезки (`pagination.rs:287-313`)
`min_split = find_next_char_boundary(remaining, 1)`, это длина первого символа (≥ 1, потому что `remaining` непуст: `start_offset < len`). Начальный `split_len` равен либо `best_split > 0`, либо `min_split`. Любая ненулевая граница символа ≥ `min_split`, поэтому `split_len ≥ min_split`.
- Выход: `final ≤ budget` **или** `split_len ≤ min_split`.
- Иначе `split_len > min_split`, `new_len = split_len − max(split_len/10, 1) < split_len`, `fvcb(new_len) ≤ new_len`. Затем берется `.max(min_split)`: результат либо `< split_len`, либо равен `min_split < split_len`.

`split_len` строго убывает и ограничен снизу числом `min_split`, значит цикл завершается. Шаг убывания геометрический (10%), поэтому итераций O(log n). Слайсы `remaining[..split_len]` всегда берутся на границе символа. Единственный случай превышения бюджета: тело уже сжато до `min_split`, но футер все равно не помещается. Это и есть «бюджет < ~60» из п. 1.4.

### 2.3. Эмпирический зонд (временный тест, удален)
Был добавлен временный файл `crates/ci-mcp/tests/zz_probe_tmp.rs`, после проверки удален вместе с пустым каталогом `tests/`. Каталог `crates/` в git не отслеживается (`??`), поэтому `git diff --stat crates/` пуст и до, и после. Неизменность дерева подтверждена сравнением sha256 всех 21 файла `crates/` до и после: **IDENTICAL**.
- Входы: кириллица+emoji, сплошные emoji, CJK, комбинирующие диакритики, ZWJ-последовательности, ASCII без пробелов, только `\n`, смешанный код, `"a"×50000`.
- Бюджеты: 64, 65, 70, 80, 100, 128, 200, 500, 4000; `stale` true/false (в debug-прогоне не дошло до конца из-за медленного BPE). Полный release-прогон: бюджеты 64/100/4000 при `stale=true`, 27 комбинаций.
- Проверялось: склейка всех страниц == исходник, `token_count ≤ budget` на каждой странице, поле `tokens:` футера == факт, нет пустых тел при `truncated=true`, есть завершение.
- **Результат: 0 нарушений по всем проверкам**, зависаний нет. Максимум ровно 64 при бюджете 64.
- Курсоры: смещение внутри символа снэпается корректно; смещение `usize::MAX` → пустой конец, без паники; мусорный курсор → молча начинается страница 0. `page = usize::MAX` → **паника `attempt to add with overflow` на `pagination.rs:292` в debug/test** (F6).
- Только пробелы/переводы строк (20000 символов) → `token_count 0`, отдается целиком без обрезки (F7).
- Производительность (release, бюджет 4000, один вызов): `"abcdefghij"×3000` (30 KB) — 2.0 s; `"a"×50000` — 6.0 s; случайный base64 100 KB — 28 ms. Обход `"a"×50000` при бюджете 64 занял 192 s на 707 страниц (F8).
