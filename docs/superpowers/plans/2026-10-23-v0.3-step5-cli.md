# v0.3 Step 5 — `context-init` bin over `ci-*` crates — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close Step 4 acceptance findings, move the real analysis pipeline into `ci-core`, make the binary a thin CLI over `ci-core`/`ci-llm`/`ci-mcp`, and add `config`, `migrate`, `setup`, `telemetry`, `feedback` plus `--model`/`--role`.

**Architecture:** `ci_core::analysis` (deterministic detect → generate/update, AST packer) is the single pipeline. `ci_llm::enrich` optionally enriches it through `RoleRouter`. `ci-mcp` handlers and `src/cli/*` both call that pipeline. The knowledge base lives in central storage (`StoragePaths::project_knowledge_dir`).

**Tech Stack:** Rust 2021 workspace, clap 4 derive, rmcp 3.5.1, syn 2, serde_json, toml / toml_edit, similar (diff), tiktoken-rs, cargo-nextest.

**Spec:** [docs/superpowers/specs/2026-10-23-v0.3-step5-cli-design.md](../specs/2026-10-23-v0.3-step5-cli-design.md)

## Global Constraints

- Every shell command is prefixed with `rtk`. Use `rg`/`fd`; never GNU `find`/`grep`.
- Before cargo: `export PATH="${__MISE_ZSH_ACTIVATE_PATH:-$HOME/.local/share/mise/shims}:$PATH"`. Abbreviated below as `$CARGO_ENV`.
- Zero mentions of «1С»/«1C» (the product) in code, comments and tests.
- The runtime knowledge base lives in `~/.local/share/context-init/projects/<project-id>/`. Only `AGENTS.md` and skills are written into the repo.
- Dependency direction is fixed: `ci-llm → ci-core`, `ci-mcp → ci-llm + ci-core`, bin → all. `ci-core` never depends on `ci-llm`.
- The deterministic mode is the default. A role with no alias = `none`.
- `MIN_RESPONSE_TOKENS = 64`. `config validate` errors below it; `Config::load` only warns.
- Subsystem id pattern: `^[a-z0-9][a-z0-9_-]{0,63}$`.
- `pack all` limit: estimated tokens > `5 × max_response_tokens` → refusal.
- `setup` registers at user level only. It merges only the `context-init` key, backs up to `<file>.bak.<YYYYMMDD-HHMMSS>` before writing, writes nothing when unchanged, and uses `command = current_exe()`, `args = ["mcp"]`.
- Rule blocks use the markers `<!-- context-init:begin -->` / `<!-- context-init:end -->`. The rule text is ≤ 15 lines.
- `telemetry --submit` always asks for confirmation unless `--yes`. Tests never create real issues.
- Gate per task: `rtk cargo clippy --workspace --all-targets -- -D warnings` is clean and the task's tests pass. Wrap every test run in `timeout 300`.

## Review Focus

1. **Existing user config files with unusual content** (comments in `~/.codex/config.toml`, a huge `~/.claude.json`, trailing commas / invalid JSON). Expected: comments preserved; invalid file → error, file untouched. Tests are in Task 12.
2. **A project already initialized in-repo (legacy `.agents/knowledge`) and never migrated.** `check`, `pack` and MCP reads should still work via lazy fallback, and `init` must not silently create a divergent central copy without saying so. The test is in Task 9: `cli_check_reads_legacy_in_repo_knowledge`.
3. **An agent-kind model configured, but the user runs the CLI (no harness to answer).** Expected: a deterministic result plus a warning, not a hang or an error. The test is in Task 7: `enrich_agent_kind_from_cli_falls_back_with_warning`.
4. **Paths with spaces / non-UTF-8-safe characters in `current_exe()` or home dirs.** Expected: written as a proper JSON/TOML string, round-trips on re-read. The test is in Task 12: `setup_exe_path_with_spaces_roundtrips`.
5. **Re-running commands (`setup --write`, `migrate`, `init`) twice.** Expected: idempotent; no duplicate rule blocks; `migrate` errors without `--force`. Tests are in Tasks 11 and 13.
