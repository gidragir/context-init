# ADR 0002: Обязательное оборачивание JSON в объект для локальных SLM (Ollama)

- **Статус:** Принято
- **Дата:** 2026-10-09
- **Область:** Подсистема интеграции с Ollama (`src/ollama.rs`)

## Контекст
При обращении к локальным SLM (`qwen2.5:14b-ctx64k`) через Ollama API с параметром `format: "json"`, запросы на генерацию сырого массива `[...]` часто приводят к деградации: модель возвращает единичный объект `{"id": ...}` либо последовательность объектов с дублирующимися ключами в одном объекте.

## Решение
1. Все промпты для генерации структурированных списков через Ollama обязаны требовать корневой объект-обертку:
   ```json
   {"subsystems": [{"id": "...", "name": "...", "summary": "...", "tags": ["..."]}]}
   ```
2. Десериализатор клиента в `src/ollama.rs` обязан поддерживать эластичный парсинг:
   - Парсинг обертки `Wrapper { subsystems: Vec<T> }`;
   - Парсинг прямого массива `Vec<T>`;
   - Парсинг одиночного объекта `T` с заворачиванием в `vec![t]`;
   - Очистку от Markdown code blocks (```` ```json ````).

## Последствия
- Полное устранение сбоев парсинга ответов модели при сохранении строгого JSON-контракта.
- Корректная работа эвристического отката при недоступности или непредвиденных ошибках инференса.
